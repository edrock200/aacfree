# v0.4 review → proposed v0.5 plan

Date: 2026-11-12 · Version reviewed: 0.4.0

## Method

Nine independent reviewers each read the code along one dimension: data integrity, core talk loop, alternative access, languages, grown-up/caregiver flows, platform (PWA and Android), security and privacy, market comparison, and code quality/CI. The reviews were read-only. `npx tsc --noEmit -p .` is clean and `npm test` passes (5 files, 70 tests). Nobody ran the app on a device or ran the Playwright e2e, so the Android WebView and browser-policy findings rest on code reading and platform knowledge.

A second, adversarial pass then tried to refute each finding against the code.

| | Count |
|---|---|
| Findings raised | 129 (113 defects/gaps, 16 market features) |
| Confirmed as stated | 35 |
| Partly confirmed (severity or sub-claims corrected) | 22 |
| Refuted outright | 0 (9 sub-claims refuted, see appendix) |
| Unverified: verification cap reached | 15 |
| Not sent for verification (mostly low severity and feature ideas) | 57 |

Of the 57 verified findings, verification lowered the severity of 29. After merging duplicates across dimensions there are 5 high, 27 medium and 11 low confirmed defects, plus 13 unverified medium items. No critical defects were found.

Severity scale: critical (data loss, crash, user can't communicate, security hole), high (a core flow is broken or badly degraded for a real user group), medium (a noticeable defect or important gap), low (polish). In the table, **C** = confirmed, **P** = partly confirmed with the corrected severity shown, **U** = unverified.

## Overall verdict

Caleb 0.4.0 is in good shape for the common case: an English-speaking touch user on Android. The talk loop, the motor-planning rules, the save pipeline and the encryption are careful work. No reviewer found a way for an ordinary user to lose their boards or their voice.

The problems are at the edges added since v0.2:

- **Non-English profiles.** Starter words, layout change, the voice picker, label edits and verb conjugation were written for English and break in Spanish, French and Portuguese.
- **Alternative access.** Scanning and the dwell/head/eye pointer fire unintended selections in several ordinary situations (held switch, new board under a resting pointer, lost face).
- **Sync.** The merge keeps the wrong side in its own headline use case.
- **Recovery paths.** Three rarely used paths (unreadable data at startup, the crash-screen restore, backup after a failed load) overwrite data without keeping a copy first.
- **Tests.** None of the above is covered. The persistence engine, the scanner state machine and the shipped verb lists have no tests.

### Strengths

- Saves are revision-checked in one IndexedDB transaction, and a failed read blocks saving, so an unreadable database is not overwritten.
- Restore validates before writing, snapshots first and clears undo. Asset GC honours snapshots and a 24 h grace period; no path was found that deletes a referenced asset.
- Motor planning holds throughout: fixed paging, padded pages, hidden words keep their slot, add-word appends a row, resize keeps positions.
- The quick bar is on every non-grown-up screen, and the Android back button never exits.
- `usePress` is one consistent abstraction for hold, debounce and switch/dwell activation.
- The language-pack design is sound: English-keyed vocabulary and exact positional round trips. All 556 wrapped UI keys exist in es/fr/pt with matching placeholders.
- Encryption is right for the purpose: AES-256-GCM, fresh salt and IV per file, and the backup passcode never goes into backups.
- No `dangerouslySetInnerHTML`, no arbitrary remote fetches from imported files, an escaped print view with its own CSP, and a non-exported FileProvider.
- The service worker update is prompt-mode, the precache is modest (769 entries, about 5.1 MB), and CI pins the release certificate.
- For a free app the feature breadth is unusual: masking with reveal, step-by-step Find word, scanning, dwell/head/eye access, schedules, OBF, encrypted sync and four languages.

### Low-severity items not sent for verification

Each was read by one reviewer only. Treat them as leads.

- **Usage log and return-home skipped for long-press forms** (`src/screens/TalkScreen.tsx:144`): route the pick through `pressButton`.
- **Nonsense English forms** for function words ("whats / whating", "mies") and "quiting" (`src/lib/morphology.ts:168`).
- **Overlapping playback** when two recorded-voice buttons are tapped quickly: no token re-check after the await (`src/lib/tts.ts:101`).
- **`deleteProfile` continues when its safety snapshot fails**, with an unhandled rejection (`src/store.ts:367`).
- **Keyboard screen hijacks Enter and Space** for focused buttons outside the key grid (`src/screens/KeyboardScreen.tsx:74`).
- **Gaze calibration** records stale samples when the face is lost and accepts a garbage fit; head mode has no hands-free re-centre (`src/components/GazeCalibration.tsx:38`).
- **Text size** scales only a few components; nav labels are about 11 px (`src/styles/app.css:267`).

## New features ranked by impact

From the market review (Proloquo2Go, TD Snap, LAMP, TouchChat; the best-sourced evidence is the "Aging Up AAC" interview study, arXiv 2404.17730) and other reviewers. Web research on CoughDrop, Avaz and Grid was thin.

1. **Output control for the person: Stop, volume, text-only** (M). The Speak button becomes Stop while speaking; today stopping means clearing the message. An optional "My voice" panel, never behind the lock, offers three volume presets, a speed stepper and "Show, don't speak" (routes to Big text). Controls use `usePress` and are scannable.
2. **Control over recent sentences** (S). Per-row delete and "Clear recent" without the lock, a `keepRecent` setting (on / session / off), and a "Private for now" toggle that pauses history and the usage log. Covers defect 54.

Build sets by tapping words in edit mode; show a "Practising: Bubbles" chip with an end button. The quick bar stays complete.

8. **Highlight words as they are spoken** (M). A `speakingIndex` in the store, driven by `onboundary` on web and by the plugin's range event or a timing estimate on Android. Border only under Reduce motion.
9. **Better prediction** (M). A second pass by edit distance and a simple phonetic key when prefix hits run out, the symbol beside a suggestion, an abbreviations list, and long-press to forget a learned word. Build on the tokeniser fix (defect 15).

## Appendix: refuted claims

No finding was refuted outright. These sub-claims were, and should not be re-raised:

- **"The crash-screen restore skips validation."** `init()` runs `migrate()` on the restored data after reload.
- **"The unchecked crash-screen save loses data via stale `rev`."** The effect is the reverse: a stale flush can undo the restore.
- **"Reduce motion removes the hold-to-activate fill and the Grown-ups keep-holding bar."** Both are `::after` pseudo-elements, which the reduce rule does not match.
- **"`ErrorBoundary` has no `t()` call at all."** Its heading, body and buttons are wrapped; only three `alert()` strings are not.
- **"Auditory scanning reads untranslated aria-labels aloud."** None of the cited elements is a scan item; the gap affects screen readers only.
- **"Starring a recent sentence creates a second, English Favorites group beside a translated one."** No translated Favorites group exists; there is one group, always named in English.
- **"Taking a photo for a button kills the camera pointer."** The engine is already stopped in edit mode.
- **"`PointerEngine.update()` has the same start/stop race."** It is dead code: `PointerLayer` recreates the engine on a mode change.
- **"A compromised `action-gh-release` tag could exfiltrate the keystore."** The release job is separate and never sees the signing secrets.

Other corrections to keep in mind:

- An `aboutMe` string hides the tool; it does not crash.
- The dwell ring is drawn at the screen centre while it counts down; it is not invisible.
- The onboarding voice list is already filtered by language; only the preview text and the "Device default" preview are wrong.
- "Pagado" is a valid Portuguese participle.
- Sync files are always encrypted, so the plaintext-PIN issue applies to backups only.
